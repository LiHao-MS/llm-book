# 面向计算机研究生的大语言模型数字教材：设计文档

- 日期：2026-10-14
- 状态：已确认（2026-10-14）
- 工作标题：`理解大语言模型：从数学基础到强化学习与 Scaling`（后续可改）

## 1. 意图与背景

本项目是一本**网页优先、可导出正式 PDF 的大语言模型教材**，不是模型演示应用，也不是新闻或 API 教程合集。它面向计算机专业研究生，从数学与机器学习基础开始，逐步进入 Transformer、预训练、Scaling、后训练与强化学习、推理系统和前沿研究。

用户希望内容严肃、准确、由浅入深，同时通过充分的图示和适量交互降低理解门槛。用户以内容提示和方向反馈为主，章节划分、具体详略和主要写作由助手承担。

## 2. 读者与使用约束

- 主要读者：计算机专业研究生，以及具备相近工程和数学学习能力的技术读者。
- 默认语言：简体中文；首次出现的重要概念保留英文术语，论文标题和模型名保持原文。
- 基础部分服务于 LLM 主线，不扩展成与后续无关的通用数学或机器学习教材。
- 读者不应被要求拥有 GPU、大模型 API 或昂贵算力。核心学习和全部交互必须在普通浏览器中完成。
- 网站以公开阅读为主，暂不需要账户、评论、付费、数据采集或服务端动态能力。

## 3. 目标

1. 用同一份内容源维护网页和正式 PDF，避免两套书稿逐渐分叉。
2. 建立从数学、机器学习到当前 LLM 技术路线，再到 RL、Scaling 和前沿议题的连贯学习路径。
3. 让可视化成为主要教学手段之一，而不只是装饰；交互用于操纵关键变量、观察因果变化。
4. 支持公式、代码、图表编号、跨章引用、参考文献、练习和进一步阅读。
5. 保持内容长期可维护，适合 Git 协作、审阅、版本化发布和后续更新。
6. 使用静态网站架构发布到 GitHub Pages，不依赖后端或特定托管平台。

## 4. 非目标与反目标

### 非目标

- 不追求覆盖所有数学、机器学习或深度学习知识，只讲与 LLM 主线有明确联系的内容。
- 不训练真实大模型，不要求读者复现需要大规模算力的实验。
- 不把交互式玩具替代正式解释、数学定义、代码和论文证据。
- 不建设通用博客、社区、课程平台或商业 SaaS。
- 首期不接入魔搭、VPS、数据库、用户系统或任何服务端推理。

### 反目标（出现即说明设计失败）

- 章节成为互相孤立的知识点或 Demo，缺少由浅入深的主线。
- 页面视觉效果压过正文，或交互只追求“好玩”而没有明确教学问题。
- 网页与 PDF 分别维护，或 PDF 因交互内容缺失而不完整。
- 为追逐前沿而堆砌名词，缺少必要推导、适用条件和局限性说明。
- 核心内容依赖外部模型 API、在线服务或大文件下载才能理解。

## 5. 内容架构

全书采用七个部分。具体章节标题和拆分由作者根据写作连贯性调整，但不得丢失以下主线。

### 第一部分：为 LLM 准备的数学基础

- 线性代数：向量、矩阵、内积、投影、特征分解、SVD、低秩表示。
- 概率与统计：条件概率、期望、常用分布、最大似然、采样与估计。
- 信息论：熵、交叉熵、KL 散度及其与 NLL 的关系。
- 优化：经验风险、梯度下降、SGD、Momentum、Adam/AdamW、学习率调度、Warmup、梯度裁剪、权重衰减。
- 数值计算：稳定性、Softmax、Log-Sum-Exp、精度与舍入误差。

### 第二部分：机器学习与神经网络基础

- 监督、无监督、自监督学习；训练、验证、测试与泛化。
- 偏差—方差、正则化、数据泄漏和评估陷阱。
- 损失函数的系统比较，以及损失选择如何塑造模型行为。
- MLP、激活函数、反向传播和自动微分。
- 初始化、归一化、残差连接、梯度消失与爆炸。
- Embedding 与表示学习；RNN 等序列模型只作为理解 Transformer 的历史和对照。

### 第三部分：Transformer 与大语言模型

- Tokenization、Embedding、Logits、Softmax 和下一词预测。
- Next-token Cross-Entropy、Teacher Forcing、Perplexity。
- Self-Attention、Multi-Head Attention、Mask、Q/K/V 的几何与计算解释。
- 位置编码、RoPE 等方法；归一化、残差和前馈网络。
- 完整 Transformer Block 与 Decoder-only 架构。
- 训练与推理的差异；贪心、温度、Top-k、Top-p 等解码策略。

### 第四部分：预训练、Scaling 与训练系统

- 预训练语料、清洗、去重、质量、配比和评测污染。
- 数据、参数、算力与损失之间的 Scaling Laws；计算最优和数据受限等讨论。
- 混合精度、梯度累积、数据/张量/流水线并行及显存权衡。
- MoE、稀疏激活、路由和负载均衡。
- 长上下文、注意力效率及架构变体；稳定知识与时效性研究分开处理。

### 第五部分：强化学习、后训练与对齐

- MDP、回报、价值函数、Bellman 方程、Monte Carlo 与 TD。
- Policy Gradient、Actor-Critic、PPO 及重要采样比率。
- SFT、指令微调、奖励模型和偏好数据。
- RLHF 中的奖励、KL 约束、Value Loss、Entropy Bonus 和 PPO Clipping。
- DPO 等直接偏好优化方法及其与 RLHF 的目标差异。
- RLVR、过程反馈、可验证奖励、Agentic RL、环境设计和 Reward Hacking。
- 前沿 RL 内容以原始论文和可复现实验为依据，明确写出假设和未解决问题。

### 第六部分：推理与系统工程

- GPU 计算与显存层次、延迟、吞吐和批处理。
- KV Cache 的容量和访问成本。
- 量化、蒸馏、投机解码、连续批处理和服务优化。
- 训练目标、模型结构与推理成本之间的联系。

### 第七部分：前沿专题与开放问题

- 推理时计算、搜索、验证和测试时 Scaling。
- 工具调用、Agent、长期任务、记忆与环境交互。
- 多模态模型及统一表示。
- 长上下文、检索与上下文管理。
- 评测、安全、可解释性和开放研究问题。

## 6. 章节教学结构

各章可按内容调整，但默认包含以下要素：

1. 学习目标与必要先修知识。
2. 一个具体问题或直觉冲突作为引入。
3. 直觉解释和图示，再给出数学定义与必要推导。
4. 最小、可读的 Python 示例；前期以 NumPy 为主，进入神经网络后使用 PyTorch。
5. 至少一幅承担解释任务的图；适合时加入一个可交互版本。
6. 常见误解、边界条件或失败模式。
7. 小结、练习、参考文献和进一步阅读。
8. 网页交互对应的静态图、表格或文字后备内容。

写作应区分稳定基础与快速变化的前沿结论。前沿内容优先引用原论文、官方技术报告和可复现材料，并标注发布或更新日期；厂商自报结果不得直接写成独立验证的结论。

## 7. 可视化与交互原则

可视化是本书的一等教学内容，但每幅图必须回答一个明确问题，例如“温度改变后概率质量去了哪里”，而不是仅让页面更热闹。

优先设计的主题包括：

- 向量、矩阵、低秩近似与 Embedding 几何。
- Softmax、交叉熵、KL 散度和困惑度。
- SGD、Momentum、Adam/AdamW 在玩具损失曲面上的轨迹。
- 学习率、Warmup、梯度裁剪与训练稳定性。
- Attention Score、Mask、注意力矩阵和多头差异。
- RoPE 的旋转几何和相对位置直觉。
- 温度、Top-k、Top-p 对采样分布的影响。
- Scaling Law 中参数、数据、算力和损失的权衡。
- MoE 路由与负载均衡。
- PPO Ratio、Clipping、KL 惩罚和 Reward Hacking。
- KV Cache 大小、量化误差、吞吐与延迟。

资源约束：

- 默认使用小型内置数据或构建时生成的精简 JSON，不加载模型权重。
- 交互优先使用浏览器原生 JavaScript、SVG 和 Canvas；计算量应适合普通笔记本和手机。
- 不为简单交互引入 React、Vue 或大型可视化框架。确需第三方库时，需由具体功能证明其必要性。
- 重型实验在构建期生成静态结果，读者端只探索已计算的数据。
- 交互应可键盘操作、具备文字说明，并尊重减少动态效果的用户设置。
- **不变量：任何只存在于交互中的关键知识，都必须有 PDF 可呈现的等价静态表达。**

## 8. 技术架构

### 内容与出版

- 使用 **Quarto Book** 和 `.qmd` 文件作为唯一内容源。
- 使用 Pandoc Markdown 书写正文、公式、代码和交叉引用。
- 使用 BibTeX/BibLaTeX 文献库及 CSL 样式管理引用。
- 网站使用 Quarto HTML Book，保留章节导航、全文搜索、代码高亮和跨章引用。
- PDF 使用 Quarto 的 Typst 输出，并通过自定义 Typst 模板处理封面、章节页、中文字体、页眉页脚和代码样式。
- 使用 Quarto 条件内容区分网页交互与 PDF 静态后备，不复制正文。

Quarto 官方文档确认 Book 支持 HTML、PDF、Typst 等输出，HTML Book 支持全文搜索和跨章引用，Typst 支持 Book 项目（doc，2026-10-14 查阅）。

### 前端与视觉

- 自定义 SCSS/CSS 控制排版、色彩、图示和响应式布局，不另起 React/Vue 应用。
- 交互组件使用原生 ES Modules，按页面加载；图形优先 SVG，粒子或高频绘制场景才考虑 Canvas。
- 各交互尽量实现为独立、可复用的小组件，使其不依赖某一章的正文结构。
- 图像优先使用矢量格式；复杂图在构建时生成，避免把截图当作主要教学图。
- 使用 Quarto/MathJax 的数学渲染能力和 Typst 的数学排版能力，不在不同输出中手写两套公式。

### 代码与可复现性

- 轻量示例可在构建或 CI 中执行，避免代码与正文结果失配。
- 依赖重型模型、大语料或 GPU 的示例默认不执行，只提供可阅读代码和预先保存的结果。
- 示例必须说明张量形状、输入输出和关键超参数，避免只给不可运行的伪代码。
- 数值示例应使用固定种子或固定输入，保证网页和 PDF 结果一致。

## 9. 构建与 GitHub Pages 部署

- GitHub 仓库保存源稿、图示源文件、交互组件、参考文献和构建配置；生成物不作为主要编辑对象。
- GitHub Actions 安装固定版本的 Quarto 和必要依赖，构建 HTML Book 与 Typst PDF。
- HTML 构建产物通过自定义 Actions 工作流发布到 GitHub Pages；PDF 作为站内可下载产物一并发布。
- 项目页路径（`/<repository>/`）必须在本地预览和 CI 中正确处理，资源不能硬编码为域名根路径。
- 暂不配置魔搭镜像或 VPS；静态产物保持平台无关，未来可直接增加发布目标。
- 大视频、数据集和模型权重不进入 Pages 构建产物。站点体积、带宽和构建时间应纳入发布检查。

GitHub Pages 当前官方限制包括发布站点不超过 1 GB、每月 100 GB 软带宽限制，以及静态 HTML/CSS/JS 托管模式；公开仓库可免费使用并支持自定义域名与 HTTPS（doc，2026-10-14 查阅）。

## 10. 质量验证

每次发布前至少验证：

- HTML 和 Typst PDF 均能从干净环境成功构建。
- 无未解析的交叉引用、缺失图片、数学公式错误或失效站内链接。
- 关键交互在最新桌面浏览器和移动尺寸下可用，且无后端时功能完整。
- 交互的静态后备在 PDF 中存在且语义等价。
- 代码示例的输出与正文一致；需要执行的轻量示例在 CI 中运行。
- 页面具备基本可访问性：对比度、键盘操作、图注、替代文本和减少动态效果。
- 首个样板章需要人工检查 PDF 的中文字体、分页、图表和公式，而不能只确认文件生成成功。

## 11. 垂直切片与后续推进

首个实现里程碑只做**一个完整纵向样板**，不先铺全部目录：

- 建立最小 Quarto Book、HTML/Typst 双输出、GitHub Actions 和 Pages 发布。
- 完成样板章“从 Softmax 到交叉熵：语言模型如何学习下一个 Token”。
- 样板章包含必要数学、最小 Python 示例、静态示意图、至少两个低资源交互和对应 PDF 静态后备。
- 通过该样板验证阅读体验、视觉风格、构建链路和 PDF 质量，再批量展开其余章节。

后续按内容主线逐部分写作；每一部分都保持网页、PDF、练习、引用和交互后备同步完成，而不是先写完全部文字再补图。

## 12. 已决定事项与实现者自由度

### 用户已确认或明确表达

- 网页为主，同时保留正式 PDF。
- 从数学与机器学习基础开始，覆盖到前沿 RL 和 Scaling。
- 面向计算机专业研究生，内容严肃但表达生动。
- 加强帮助理解 LLM 的可视化，核心体验不依赖昂贵资源。
- 使用 GitHub Pages，不采用魔搭或 VPS 作为首期部署目标。
- 章节具体安排由助手把握，用户通过内容提示补充关注点。

### 本设计作出的实现选择

- Quarto Book + Typst，而不是 Astro/MDX 双出版管线。
- 原生 JavaScript 交互，而不是前端框架驱动整站。
- 首个样板聚焦 Softmax、交叉熵和下一词预测，用它验证完整出版链路。
- 中文正文、英文术语保留、GitHub Actions 构建并发布。

### 实现者可自行决定

- 具体目录文件名、章节编号、CSS 视觉细节和组件内部实现。
- 不破坏双输出和低资源约束的构建工具、检查工具及辅助库。
- 各章的细分、顺序微调、例子和练习设计。

### 后续由用户决定但不阻塞样板

- 正式书名、公开仓库名称和是否使用自定义域名。
- 内容与代码的开源许可证。
- 是否公开接受外部贡献及其审阅流程。

## 13. 可实施性检查后的补充决定

以下事项由本设计明确，不再留给实现阶段猜测：

- **整体规模**：完整版参照约 400–500 页的研究生教材，目标 40–50 章；第一、二部分合计约占四分之一，其余篇幅用于 LLM 主线、RL、Scaling、系统和前沿。完成标准是主线覆盖与章节质量，而不是机械凑页数。
- **反馈节奏**：首个纵向样板完成后设置一次明确验收点；样板通过后按部分持续写作和发布草稿，用户异步反馈，不为每一部分设置硬等待门。只有改变整体范围、出版架构或部署目标时才重新请求确认。
- **PDF 后备路线**：Typst 是首选而不是牺牲正式 PDF 的硬限制。若样板在中文字体、公式、交叉引用或版式上暴露 Quarto + Typst 的实质限制，允许改用 Quarto + LaTeX 生成 PDF；仍必须坚持同一 `.qmd` 内容源，不建立第二套书稿。
- **案例立场**：保持厂商中立。基础原理使用玩具模型和可复现计算，案例研究优先选择论文、技术报告和开放权重模型；国内外模型按技术价值纳入，不把书写成特定产品教程。
- **中文搜索质量**：搜索必须能处理中文，而不是仅接受 Quarto 默认组件的存在。样板阶段用“交叉熵”“梯度裁剪”“注意力”“强化学习”及“RLHF”“Scaling Law”等混合查询验收；默认搜索不满足时，替换为支持中文的静态索引方案，仍不得引入后端。
- **既有素材**：用户确认没有需要纳入的既有素材；全书从当前设计出发全新撰写。
